\subsection{Punto de acceso inalámbrico}

Configurar una Raspberry Pi, o una NUC como punto de acceso inalámbrico
(Access Point), servidor DHCP y DNS es útil para crear redes aisladas o
laboratorios de pruebas. En nuestro caso para que los estudiantes no se
conecten a internet y evitar el fraude académico.

Para lograrlo, utilizaremos principalmente dos herramientas:
\textbf{hostapd} (para el punto de acceso) \cite{raspberrypi_hotspot_2026}
\cite{malinen_hostapd_2025} y \textbf{dnsmasq} (para gestionar el
DNS y DHCP de forma ligera) \cite{kelley_dnsmasq_2024}.

\subsubsection{Preparación del Sistema}

Antes de empezar, asegúrate de que tu sistema esté actualizado
y de que tienes acceso por terminal (SSH o teclado).

\begin{lstlisting}
sudo apt update
sudo apt upgrade
sudo apt install hostapd dnsmasq
\end{lstlisting}

\subsubsection{Configurar una Dirección IP Estática para \texttt{wlan0}}

Como la Raspberry Pi o la NUC actuará como el "servidor" de la red
inalámbrica, necesita tener una dirección IP fija. Editaremos el
archivo de configuración de red:

\begin{enumerate}
	\item Abre el archivo: \texttt{sudo nano /etc/dhcpcd.conf}
  \item Añade lo siguiente al final del archivo:
\begin{lstlisting}
interface wlan0
    static ip_address=192.168.4.1/24
    nohook wpa_supplicant
\end{lstlisting}
\end{enumerate}

Esto asigna la IP 192.168.4.1 a tu Raspberry Pi o NUC en la red inalámbrica.

\subsubsection{Configurar el Servidor DHCP y DNS (\texttt{dnsmasq})}

El software dnsmasq se encargará de asignar IPs a los dispositivos
que se conecten y de resolver nombres de dominio.

\begin{enumerate}
	\item Renombra el archivo original por si acaso:
		\texttt{sudo mv /etc/dnsmasq.conf /etc/dnsmasq.conf.orig}
	\item Crea uno nuevo: \texttt{sudo nano /etc/dnsmasq.conf}
	\item Pega la siguiente configuración:
\begin{lstlisting}
interface=wlan0
dhcp-range=192.168.4.2,192.168.4.20,255.255.255.0,24h
domain-needed
bogus-priv
# Servidores DNS externos (Google)
server=8.8.8.8
server=8.8.4.4
\end{lstlisting}
\end{enumerate}
\textbf{Nota}: Aquí definimos que el rango de IPs para tus dispositivos
será de la \texttt{.2} a la \texttt{.20}.

\subsubsection{Configurar el Punto de Acceso (\texttt{hostapd})}

Aquí es donde definimos el nombre de la red (SSID) y la contraseña.

\begin{enumerate}
	\item Crea el archivo: \texttt{sudo nano /etc/hostapd/hostapd.conf}
	\item Configura los parámetros de tu red:
\begin{lstlisting}
interface=wlan0
driver=nl80211
ssid=Red_Raspberry
hw_mode=g
channel=7
wmm_enabled=0
macaddr_acl=0
auth_algs=1
ignore_broadcast_ssid=0
wpa=2
wpa_passphrase=TuContraseniaSegura
wpa_key_mgmt=WPA-PSK
wpa_pairwise=TKIP
rsn_pairwise=CCMP
\end{lstlisting}
\end{enumerate}

\subsubsection{Habilitar el Reenvío de Tráfico (IP Forwarding)}

Para que los dispositivos conectados a la Raspberry puedan salir a internet a través del cable Ethernet de la Pi, debemos habilitar el "forwarding".

\begin{enumerate}
	\item Edita el archivo: \texttt{sudo nano /etc/sysctl.conf}
	\item Busca y quita el \texttt{\#} de la línea: \texttt{net.ipv4.ip\_forward=1}
	\item Aplica las reglas de NAT para que el tráfico fluya de
		\texttt{wlan0} a \texttt{eth0}:
\begin{lstlisting}
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
sudo sh -c "iptables-save > /etc/iptables.ipv4.cache"
\end{lstlisting}
\end{enumerate}

\subsubsection{Puesta en Marcha}

Finalmente, debemos asegurarnos de que el sistema reconozca la
configuración de hostapd y reiniciar los servicios.

\begin{enumerate}
	\item Indica al sistema dónde está el archivo de hostapd:
			\texttt{sudo nano /etc/default/hostapd}
	\item Cambia la línea \texttt{\#DAEMON\_CONF=""} por
			\texttt{DAEMON\_CONF="/etc/hostapd/hostapd.conf"}
	\item Desbloquea el WiFi y reinicia:
\begin{lstlisting}
sudo rfkill unblock wlan
sudo systemctl unmask hostapd
sudo systemctl enable hostapd
sudo systemctl start hostapd
sudo systemctl restart dnsmasq
\end{lstlisting}
\end{enumerate}

Finalmente se debería ver una red llamada "Red\_Raspberry" desde tu
móvil o laptop. Al conectarte, la Raspberry o NUC te asignará una
IP automáticamente y podrás navegar usando su DNS.


\subsection{DNS local, sin salir a Internet}

El programa \texttt{dnsmasq} \cite{kelley_dnsmasq_2024},
además de ser un servidor DHCP,
permite crear un "DNS local".  Esto significa que se puede asignar
nombres fáciles de recordar, como \texttt{mi-servidor.local} o
\texttt{panel.control}, a direcciones IP específicas sin necesidad
de salir a internet \cite{raspberrypi_forums}.


\subsubsection{Asignar nombres mediante el archivo \texttt{/etc/hosts}}

La forma más sencilla de que dnsmasq asigne nombres a IPs estáticas es
leyendo el archivo de hosts local de la Raspberry Pi.

\begin{enumerate}
	\item Abre el archivo: \texttt{sudo nano /etc/hosts}
	\item Añade tus dispositivos al final del archivo siguiendo este
		formato: \texttt{IP\_del\_dispositivo  nombre\_deseado}. Por ejemplo:
\begin{lstlisting}
192.168.4.1   pi.local
192.168.4.10  impresora.local
192.168.4.15  camara.local
\end{lstlisting}
	\item Guarda y cierra (\texttt{Ctrl+O}, \texttt{Enter}, \texttt{Ctrl+X}).
\end{enumerate}

\subsubsection{Configurar dnsmasq para leer esos nombres}

Ahora debemos asegurarnos de que \texttt{dnsmasq} esté escuchando
y resolviendo esos nombres para todos los dispositivos conectados
al Access Point.

\begin{enumerate}
	\item Edita el archivo de configuración: \texttt{sudo nano /etc/dnsmasq.conf}
	\item Asegúrate de que estas líneas estén presentes (o añádelas):
\begin{lstlisting}
# Añade el dominio automáticamente a los nombres simples
expand-hosts

# Define el dominio local
domain=local

# Escucha solo en la interfaz de la red local
interface=wlan0

# Evita que se reenvíen nombres sin puntos a los servidores DNS externos
domain-needed
bogus-priv
\end{lstlisting}
\end{enumerate}

\subsubsection{Asignación de nombres por DHCP (Opcional)}

Si se quiere que los dispositivos que se conectan por DHCP reciban
siempre la misma IP y tengan un nombre asignado automáticamente,
añade esto al mismo archivo \texttt{/etc/dnsmasq.conf}:

\begin{lstlisting}
# Formato: dhcp-host=MAC_ADRESS,NOMBRE,IP,TIEMPO_DE_CONCESION
dhcp-host=AA:BB:CC:DD:EE:FF,portatil-juan,192.168.4.50,infinite
\end{lstlisting}

Se puede ver las direcciones MAC de los dispositivos conectados
actualmente ejecutando el comando \texttt{arp -a}.

\subsubsection{Reiniciar y probar}

Para que los cambios surtan efecto, reinicia el servicio:

\begin{lstlisting}
sudo systemctl restart dnsmasq
\end{lstlisting}

\textbf{Cómo Probarlo:}
Desde cualquier dispositivo conectado a la red WiFi de tu Raspberry
Pi o NUC (tu móvil o laptop), abre el navegador o la terminal e
intenta hacer un "ping" al nombre que configuraste:

\begin{lstlisting}
ping pi.local
\end{lstlisting}

\textbf{Un detalle importante}: Si estás usando el dominio \texttt{.local},
ten en cuenta que algunos sistemas operativos (como iOS o macOS)
usan este dominio para el protocolo mDNS (Bonjour). Si ves que no
resuelve bien, prueba cambiando el dominio a algo como \texttt{.home} o
\texttt{.pi} en el archivo de configuración.
